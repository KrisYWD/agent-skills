# 行文自查与 codex 复查

这份清单来自一次真实的精修：两遍 codex 复查查出 184 条，自查约 20 条。下面的例子全是**真出现过**的毛病，不是设想的。

## 五类毛病

### 一、翻译腔、书面语过重、学术腔

专利和论文语料读多了，会不自觉地把它们的文体带进正文。车间里的人不这么说话。

| 写成了 | 应该写 | 病根 |
|---|---|---|
| 公开教导可自由使用 | 公开的技术方案可以自由使用 | patent teaching 直译 |
| 电晕是表层偏置的 | 电晕充电后，电荷更集中在表层 | surface-biased 直译 |
| 法规侧成熟了，科学侧断着 | 法规路径已成熟，科学证据链仍不完整 | side 直译 |
| 多年未能商业穿透 | 多年未能实现规模商业化 | commercial penetration 直译 |
| 价格是一个很宽的篮子 | 价格跨度很大 | 英文比喻直搬 |
| 不是全称命题 | 这条不是放之四海皆准的 | 逻辑学术语 |
| 「慢冷有利」的泛化 | 「慢冷有利」这句通则 | 名词化的学术腔 |
| 这个指标本身就不闭合 | 这个指标不完整，没法拿来比 | 抽象术语，没说后果 |
| 事后无法回填 | 一旦错过就无法补测 | 数据处理术语用错场景 |
| 所有跨研究的数字 | 所有来自不同研究的数据 | cross-study 直译 |

**判据**：这句话你会对着车间主任说出口吗？不会就是学术腔。

### 二、句子结构别扭

主语丢失、成分残缺、连词缺失、长定语套叠。**这类是真语法错误，而且自查最容易漏——同一个模型看不出自己写的句子有毛病。**

| 写成了 | 病在哪 |
|---|---|
| 卡点不在技术在意愿 | 并列分句缺「而」，后半句缺主体 |
| 熔喷不会被替代，会被「配方多样化」 | 「被配方多样化」动宾关系不成立 |
| 8 件负载样是 5 件通过 | 「试样是……通过」主干不通 |
| 后者仍在有效期与后续族内 | 把时间和专利族硬并在一起 |
| 呼吸舒适度的增量应该到……里去找 | 「增量」和「去找」搭配生硬 |
| 询能否供卷、能否给三卷统计 | 「询」缺宾语，「给统计」缺中心词 |
| 供应稳定性、电子成本和有效专利要求先做合作验证 | 三个名词被误当成「要求」的主体 |
| 设备采购技术要求从一开始按参数放行配置 | 让「技术要求」执行「配置」动作 |

**判据**：把句子的主干（主谓宾）单独抽出来念一遍，念不通就是这类。

### 三、用词不准或生造

自造缩略语、行业里没人这么叫的说法、同一概念前后用了不同名字。

生造过的：`可复做资产`、`批级数据`、`人因密合`、`双向系统`、`预符合设计`、`回验链`、`产品回看`、`机械地板`（floor 直译）、`坑位`、`来料交集`、`多国族分裂`、`罩体概念机`、`验收线`、`电荷埋深`、`一支 ICU 队列`（研究队列不是人员队伍）、`透气 header`（中英夹杂）。

**中英夹杂**：`仍 pending`、`EO-only 对惰性气体空白`。首次出现的英文术语给中文加括号原文，之后用中文。

**判据**：这个词在行业公开资料里搜得到吗？搜不到就是生造。

### 四、标点与数字格式不统一

- **斜杠过载**。同一份文档里斜杠不要同时承担「配方组合」「每」「并列数值」三种用法。并列数值一律用顿号：`2.10 / 0.85 / 0.46` → `2.10、0.85、0.46`。
- **`@` 是英文速记**。`121 Pa @ 95 L/min` → `在 95 L/min 流量下压降 121 Pa`。
- **倍数不要带单位**。`30—45 倍/m²` 会被读成带单位的倍数 → `每平方米价格约为熔喷的 30—45 倍`。
- **区间用一字线**，日期与标准号里的连字符不要改（`ISO 16976-2`、`2026-10-01` 是对的；`GB 18279—2023` 按国标格式用一字线）。
- **加粗标记与破折号之间不留空格**：`** ——完整橡胶` → `**——完整橡胶`。

### 五、语义含混、压缩过头

一句话塞进太多信息，或者关键词没说清指什么。

| 写成了 | 问题 |
|---|---|
| 现在要证的是整只口罩、戴在具体的人脸上以后、以及整批货 | 并列成分里混进了时间状语，三项无法共用前面的动词 |
| 增加有效面积来换阻力 | 没说阻力是升还是降 |
| 评价的对象从材料上移到了整机 | 「上移」方向不明 |
| 收益直接落在阻力上 | 同上 |
| 4 小时内累计 65% 至少一次失败 | 百分比后缺统计对象 |
| 一条容易被忽略的 / 一条要绕开 | 缺中心词，是一条什么 |
| 那两个行业已经做过的减压结构 | 前文列的是两类器械，不是两个行业 |

**判据**：把句子念给没读过上下文的人听，他能复述出来吗？

## 机械检查

这些能脚本化，跑一遍比人眼可靠。

```python
import re, pathlib
t = pathlib.Path("报告.md").read_text(encoding="utf-8")

print("═══ 符号一致性 ═══")
print("  µm(micro sign)", t.count("µ"), " vs μm(希腊 mu)", t.count("μ"))   # 必须只用一种
print("  ℃", t.count("℃"), " vs °C", t.count("°C"))
print("  半角%", len(re.findall(r"\d%", t)), " vs 全角％", t.count("％"))
print("  弯引号", t.count("“"), " vs 直引号", t.count('"'))            # 中文正文应为弯引号
print("  中英间无空格", len(re.findall(r"[一-鿿][A-Za-z0-9]", t)))  # 应为 0

print("\n═══ 套话与空转过渡 ═══")
for c in ["在当今", "众所周知", "不难看出", "值得注意的是", "毋庸置疑", "综上所述",
          "由此可见", "更重要的是", "在此背景下", "让我们", "接下来我们"]:
    if t.count(c): print(f"  {c} × {t.count(c)}")

print("\n═══ 以形容词代替证据 ═══")
for a in ["非常", "极其", "十分", "显著地", "巨大的", "颠覆", "革命性",
          "前所未有", "领先的", "先进的", "卓越", "强大的"]:
    if t.count(a): print(f"  {a} × {t.count(a)}")

print("\n═══ 超长句（>110 字要看一眼）═══")
body = re.sub(r"\*\*|`|<[^>]+>", "", t)
for line in body.split("\n"):
    if line.startswith(("#", ">", "|", "[^", "-")): continue
    for s in re.split(r"(?<=[。！？])", line.strip()):
        if len(s) > 110: print(f"  [{len(s)}] {s[:60]}…")
```

**超长句要分两种看**：参数清单（测试条件、询价项）长是对的，拆开反而难查；**论断句长就是病**，必须拆。

**术语一致性**：同一概念全文只用一个名字。检查同义词组的出现次数，如果两个都在用，统一到一个。

## 交 codex 复查

自查完了必跑。同一个模型看不出自己写的句子有毛病，换一个模型看是唯一能破自审盲区的办法。

```bash
codex exec --sandbox workspace-write --skip-git-repo-check < /tmp/codex-prompt.txt > /tmp/codex.log 2>&1
```

后台跑，prompt 从 stdin 喂（当参数传会卡在等 stdin）。prompt 模板：

```
你是一位中文技术编辑，母语级中文，长期给制造业的技术负责人编稿。

任务：逐段通读 <报告绝对路径>（一份写给<行业>技术与生产负责人的产业技术报告），
只挑**表达层面**的毛病。

要找的是这五类，其它一律不管：
1. 翻译腔、书面语过重、学术腔——车间里的人不会这么说话的句子；
2. 句子结构别扭：主语丢失、成分残缺、长定语套叠、逻辑连词用错；
3. 用词不准或生造：自造术语、行业里没人这么叫的说法、同一概念前后用了不同名字；
4. 标点与数字格式不统一：全半角混用、破折号/连接号混用、单位与数字间距不一致；
5. 语义含混：读完不知道在说什么，或一句话压缩了太多信息导致读不懂。

**不要**评论内容对错、数据真伪、结构编排、篇幅长短——那些已经定稿。
**不要**建议加内容。只改表达。

输出格式：每条一行，严格按
`行号 | 类型 | 原文片段（≤30字） | 建议改法 | 一句话理由`

要求：
- 边看边写，**每看完一章就立刻把该章的条目追加写入** <清单绝对路径>，不要攒到最后一次性输出；
- 每章开头先写一行 `## 第 N 章`；
- 宁缺毋滥：拿不准的不写。只写你有把握读者会卡住的地方。
```

**边查边写盘是必需的**——上下文压缩会吞掉攒到最后的整份产出，而 `EXIT=0` 不代表有产出。

**应用时逐条评估，不要照单全收。** 它偶尔会把行业标准术语（`实施例`、`逐权利要求`、`中试`）当成生造词。改完之后值得再跑一遍：第二遍是针对改后的稿子重查的，会抓到第一遍修改自己引入的新问题。

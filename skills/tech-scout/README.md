# tech-scout 使用教程

> 这份是给人看的，agent 不加载它。agent 读的是 `SKILL.md`。

把一个工业/制造技术方向从零查到能做决策。**调用时可以什么都不指定**——摸清你要什么是它的第一项工作，不是前提。

---

## 三条命令，三个 session

### 1️⃣ 学习

新开一个 session，输入：

```
/tech-scout
```

后面可以什么都不加，也可以只说个方向（"粉末冶金"）。

**它会做什么**：先教你一块基础概念，就这块拷问你的场景，再教下一块。交替进行。同时在后台维护两份文件——认知地图（四象限）和术语表。

**它不会做什么**：不派 subagent，不建轮次。只查证不展示过程（查完只播报一句话结论）。

**它必须从你这里问出四件事**：你在产业链哪个位置（**这条最重要**，能控制什么、不能控制什么）· 目标零件是什么 · 要拿这份调研干什么 · 什么算"调研充分"。

**什么时候算学完了 —— 展会测试**：

> **你现在去参加这个行业的展会、或者读一份行业周刊，能不能看懂？**

收尾前它会做一次**出师检验**，两半：

| | 怎么测 | 过的标准 |
|---|---|---|
| **说得出** | **合上所有材料**，把全流程从头说一遍，每道工序一句话说作用；再挑几个关键参数说它衡量什么 | 顺序和作用基本说得出 |
| **看得懂** | 一两段真实行业文本原样给你读，你标出读不通的地方 | 卡点只落在具体数值、型号、牌号 |

> ⚠️ 上半场是关键。**讲的时候全懂、讲完什么也说不出**——那就是"和看短视频没区别"的感觉，只有眼熟没有掌握。所以教学过程中它会不断让你不看笔记复述、把后面的工序连回前面的、隔几轮回头抽问。

**它会教什么**（五类，主干是流程）：

| | |
|---|---|
| 产品全景 | 有哪些产品类型、按形态怎么分、按等级怎么分 |
| 主要玩家 | 谁在做、各自什么位置 |
| **★ 全流程逐工序** | 从原料到成品每一道，**每道是干什么用的** |
| **★ 每道工序的工艺·材料·参数** | 有哪几种做法、用什么料、调什么、常见问题 |
| 关键参数定义 | 这个数什么意思、怎么算、多少算好 |

带 ★ 的两类是主干，占一半以上时间。**不教牌号和型号**——认识 3M 是必要的，背 3M 9332+ 是浪费。

**路线是活的。** 你的每一句回答都会让它重排后面要讲什么：你说"这个我懂"就跳过、你排除某条路线它就只带一句、你追问细节它就往下挖一层、你连着几次答得含糊它会退回上一级补底子。每次改路线它都会告诉你改了什么、为什么。

路线写在 `STATE.md` 的「学习路线」表里（已讲 / 正在讲 / 计划 / 降级）。**你可以直接改那张表**——比等它问对问题快。

**怎么结束**：四条全满足——出师检验两半都过、五类都覆盖了、四项必答齐了且你说 **"可以开始调研了"**。

然后它建好文件夹、出四象限图、**给你一份 `学习小结.html`**，再给一段提示词复制到新 session。

> 📄 **学习小结**是压缩后的速查表：全流程图（每格一句话说作用）· 每道工序的做法/材料/参数/常见问题 · 关键参数定义 · 全量术语表（悬停出定义）· 玩家格局 · 信息源。
> **按"站在展台前要查什么"编排，不是按教学顺序**——这是你真去展会时打开的那张纸。

**还会给你一份 `resources.md`** —— 这个行业的信息在哪：订哪几本期刊、哪些协会有公开资料库、哪几个展会值得去、招投标/海关/专利怎么查、**以及能问到人的地方**（论坛、公众号、协会活动、产业集群）。

> 💡 最后那一项别忽略。有些判断只存在于从业者脑子里，文献和检索都拿不到——**知道去哪儿问，比多查一百次有用**。

> 💡 这个阶段可能比你预期的长，而且会有几个问题你答不上来——**那正是它在起作用**。别急着跳过。
>
> ⚠️ 如果它问了几个问题就想让你开始调研，**那是抢跑**，直接说"展会测试还没过，继续教"。

### 2️⃣ 探索

新开 session，粘贴上一步给你的提示词（形如 `/tech-scout` + 目录路径）。

**每一轮八步**：

| | |
|---|---|
| ① | 从认知地图上没解决的问题生成任务书 |
| ② | **给你一屏：每路一行，标明冲着哪条问题去** ← 等你点头 |
| ③ | 派队（每路 30-40 次检索，路多切口窄） |
| ④ | 核完整性 + 交叉核对 + 跑引用校验脚本 |
| ⑤ | 出 `digest.html` 阶段报告 + 更新地图 |
| ⑥ | **你读** |
| ⑦ | **再拷问你一次** ← 这一步是这个 skill 独有的 |
| ⑧ | 判断继续还是停 |

第 ⑦ 步在检查两件事：你有没有真的看懂，以及**新知识长出了什么新方向**。你答得上来的术语会在术语表里升级，之后的报告就不再给它挂解释。

**怎么结束**：它判断够了，**并且征得你同意**。然后给你阶段三的提示词。

> 💡 停不停有三条判据一起看：证据够不够（充分 / 不足 / 拒绝定级）、本轮新证据的增量、以及剩下的问题属于哪一类——只有"查文献能答"的才值得再派，其余转成实验/询价/取档/律师四份清单。

### 3️⃣ 报告

新开 session，粘贴提示词（形如 `/tech-outlook` + 语料路径）。

产出是 A4 印刷版 HTML，麦肯锡式结构，工序为主干。**报告自带失效日期**（技术成熟度评估的公认保质期是 1-6 个月）。

---

## 中途停下来了怎么办

不用重来。**每个阶段随时可以换 session 接着走**：

```
/tech-scout

继续 <你的目录>/ ，先读 STATE.md。
```

`STATE.md` 记着当前阶段、下一步动作、各轮产出、以及**已被推翻的说法**（防止新 session 把作废的结论当结论复述）。

## 文件夹里有什么

```
<主体>/                 ← 顶层，和你其他项目平级
├── STATE.md          ← 任何 session 先读它（含学习路线表）
├── unknowns.md       ← 认知地图（四象限）。你可以直接改，改了就是在调方向
├── glossary.md       ← 术语表。你可以直接改难度状态
├── resources.md      ← 行业信息源：期刊/协会/展会/数据入口/能问到人的地方
├── learning/
│   ├── notes-NN.md   ← 讲解留档
│   └── 学习小结.html  ← 带去展会的那张纸
├── rounds/NN/
│   ├── plan.md       ← 那一屏派队计划
│   ├── briefs/       ← 各路任务书
│   ├── sources.json  ← 引用账本
│   ├── raw/          ← ★ 原始报告。最终报告的输入是这里
│   └── digest.html   ← 阶段报告
└── report/           ← 最终报告
```

**根上那四份是活文件，全程更新，你都可以直接改**：`STATE.md` 的学习路线表（改它 = 调教学顺序）· `unknowns.md`（改它 = 调调研方向）· `glossary.md`（某个术语被解释得太啰嗦，直接标"已掌握"）· `resources.md`（补你知道的信息源）。**比等它问对问题快。**

**一个主体一个文件夹，和你其他项目平级**（`powder-metallurgy/`、`锂电隔膜/` 这样）。不建 `research/` 包装层，不加日期后缀——日期在 `STATE.md` 里。

⚠️ **`raw/` 和 `digest.html` 的区别是有意的**。最终报告只能拿 `raw/` 当输入，`digest` 只能当线索地图——拿加工过的东西当输入会继承它的局限，而且改着改着就变成润色。

## 它会拒绝做的事

- **不评估"你自己接不接得住"**——它不了解你的现状，评了就是编
- **不给技术打总分**——交付的是"差多少、要做什么才能补上"
- **不问你"该关注哪些维度"**——维度由九问定死，你不知道该关注什么正是你来找它的原因
- **不出法律意见**——专利只做事实核验，FTO 和 claim chart 标为需外部律师
- **不直接改你项目的决策文档**——写成"⚠️上报总控"让你裁定

---

## 落地九问

每项技术都要回答这九条，它们也是最终技术清单的列：

成熟度 · **工艺能力与良率节拍** · 可制造性 · 谁能供 · 要投什么 · 专利 · 成本量级 · **时间窗口** · **为什么还没普及**

最后一条通常最有价值：**一项技术很好却没人用，原因往往是决定性的。**

**成熟度按"你能不能拿到"分三档**，不按技术阶段分：

| | |
|---|---|
| `【已在售】` | 有认证或批准号，买得到，能直接询价 |
| `【仅专利论文】` | 只见于专利实施例或论文样片，买不到成品 |
| `【关键参数未公开】` | 有货，但产能、报价或认证不公开，无法评估 |

这一档和 `/tech-outlook` 是同一套，阶段三不用返工。

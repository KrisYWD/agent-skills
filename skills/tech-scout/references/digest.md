# 阶段性报告（digest.html）

**用 HTML 不用 markdown。** markdown 把空间信息压平了，而这份报告要同时服务两件互斥的事：**让还在学的人读得懂，让已经懂的人读得快**。HTML 能两者兼顾，markdown 只能二选一。

单文件，内联全部 CSS/JS，不引外部资源。写到 `rounds/NN/digest.html`。

---

## 核心机制：hover 术语表

**正文里术语直接用，鼠标悬停给定义。** 懂的人读起来不卡，不懂的人一悬停就有——比"要不要解释"这个二选一好。

定义来自 `glossary.md`，按状态决定处理：

| glossary 状态 | 正文里怎么处理 |
|---|---|
| **已掌握** | 直接用，**不加 hover** |
| **已解释过** | 直接用，**加 hover** |
| **未引入** | 加 hover，**并且首次出现时正文里给半句话解释** |

```html
<span class="t" data-def="用高压惰性气体把金属液流打碎成粉，球形度高、氧含量低，比水雾化贵">气雾化</span>
```

```css
.t{border-bottom:1px dotted currentColor;cursor:help;position:relative}
.t:hover::after{content:attr(data-def);position:absolute;left:0;top:1.6em;z-index:10;
  width:min(22rem,80vw);padding:.6rem .8rem;border-radius:.4rem;
  background:var(--tip-bg);color:var(--tip-fg);font-size:.85rem;line-height:1.5;
  box-shadow:0 2px 12px rgba(0,0,0,.18)}
```

⚠️ 触屏没有 hover。给 `.t` 加 `tabindex="0"` 并对 `:focus` 同样出定义。

## 结构

### 1. 顶部状态条

一眼看到这轮在整件事里的位置：第几轮 / 派了几路 / 新增多少条证据 / 未解决 unknown 还剩几条 / 本轮推翻了几条。

### 2. 一句话结论

最大字号，独占一屏宽。

### 3. 本轮推翻了什么 ★ 放前面

**用醒目样式**（红色左边框 / 背景色）。包括推翻你自己之前说过的话。

放前面是因为**读者会凭记忆复述旧结论**，纠正必须比新增更容易被看到。

### 4. 跨路收敛

几路查不同的东西却落到同一处的，**单独成块**，标明是哪几路各自撞上的。

**收敛即论证**——这比任何单路的深度都可信，排版上要体现出来。

### 5. 技术清单表

落地九问作为列。`overflow-x:auto` 包住，页面本身不能横向滚动。

**「为什么还没普及」那一列不要省，也不要压窄**——它往往是全表最有价值的一列。

### 6. 各路发现（折叠）

`<details>` 每路一块，默认收起，摘要行写这一路的一句话结论 + 充分性条件达成率。

想细看的人展开，不想看的人不被淹没。

### 7. 认知地图变化

**这轮之前 → 之后**，并排两栏。新增的 unknown 高亮，已解决的划掉。

这是让用户直观看到"我的认知边界移动了多少"的地方，也是第四象限唯一可见的形式。

### 8. 下一轮的候选方向

从 Gaps 和更新后的地图长出来的，**每条标属于五分类里的哪一类**（文献可答 / 实验 / 询价 / 取档 / 律师）。

## 词汇难度

**按 `glossary.md` 决定，不凭感觉。** 一个术语在表里是「已掌握」就直接用，是「已解释过」就挂 hover。

**这份报告的读者是正在学的人**，和最终报告（`/tech-outlook`，读者是行业内的人、明令不许解释）不是同一个人。**不要把这份的写法带到最终报告去。**

---

## 排版底线

- **主题自适应**：`@media (prefers-color-scheme: dark)` 两套都要能看
- **响应式**：相对单位，宽内容（表格、代码）各自 `overflow-x:auto`，**页面 body 永不横向滚动**
- **图默认不画**。这种数据密度下，图往往只是正文数字的另一种排版。画之前先问：**这张图比它旁边那句话多说了什么？** 答不上来就不画
- 真要画就用内联 SVG，不引外部库

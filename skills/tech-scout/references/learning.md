# 阶段一 · 学习

**目的有两个，同等重要**：让用户建立行业基础认知，让你摸清他要什么。

没有基础认知，他提不出好问题；而探索阶段每次都停下来解释术语，会吃掉大量时间。所以这个阶段单独存在。

## 🔴 验收标准：展会测试

> **他现在去参加这个行业的展会、或者读一份行业周刊，能不能看懂？**

**这是学习阶段唯一的通过标准。** 四项必答只是你的收获，不是他的——**问完四个问题就收尾是抢跑**，实测发生过。

「看懂」的具体含义：能读懂展台参数表和技术公告的主干、能听出对方在说哪道工序、认得出被提到的公司和标准是什么来头、遇到不懂的词知道它属于哪一类。**不要求会做，要求不被挡在门外。**

⚠️ **达不到这条之前，不要提议进入探索阶段，也不要把话头往"可以开始调研了"上引。** 用户主动要走可以走，但你要如实告诉他还差什么，并在 `STATE.md` 里记明"学习阶段提前收尾"。

**不派 subagent。不建轮次。不产生任何需要被读入的中间产物。**

---

## 可以上网，但只吐结论

允许查证：某个标准号存不存在、某个参数大概什么量级、某家公司还在不在。

**展示规则**：查完只播报**一句话结论（≤30 字）**，然后继续。**不展示检索过程、原始结果或数据点。**

> ❌ "搜到 A 公司 2024 年产能 12 万吨、B 公司毛利率 23.3%、C 公司……"
> ✅ "快速扫了一下：这个细分的产能这两年在往头部集中。"

判据是机械的：**这个阶段不产生任何需要被读入的文件**。地图和术语表是你写出去的，不是读进来的。

⚠️ 遇到不确定的，当场说"我不确定"再去核。**教错的东西会污染他之后提的每一个问题**——这个阶段的产出是他的提问能力。

## 节奏：教一块，拷问一块

**先教，再问，交替进行。** 一次问 1-3 个，用户给模糊答案就继续追。

**先给全景，再走流程。**

1. 开场先花一小段讲清**这个行业在做什么产品、怎么分类分级、主要玩家各是谁**——没有这张地图，后面讲工序他不知道在往哪装
2. 然后**按产线物理顺序逐道工序走**，每道讲：这道是干什么用的 → 有哪几种做法 → 用什么料 → 调哪些参数 → 常见问题
3. 关键指标出现在哪道工序就在哪道讲透（什么意思、怎么算、多少算好），不要单开一节堆定义

每块教完立刻就这块问他的场景落在哪一档。

### 路线是活的，按他的回复重排

开场给一版路线，但**每次他回答之后都重新排一次**。下表是硬对照，不是建议：

| 他的回复里出现 | 路线怎么改 |
|---|---|
| **已经会了**——正确用了术语，或直接说"这个我懂" | **跳过，不复述。** glossary 标「已掌握」 |
| **明确排除了某条路线/某个市场** | 那一支降到"够认出来就行"，不展开 |
| **追问细节** | 这一支**加深一级**——追问是需求信号，不是打岔 |
| **答错或有误解** | **停下来纠正，优先级提到最前。** 误解会污染他之后提的每一个问题 |
| **连续给模糊答案** | 他缺下一层的底子，**退回上一级补**，别硬讲 |
| **透露出正要做的决定** | 那一支提到决策级深度，其余可以浅讲 |
| **冒出你没预设的方向** | 记进 unknowns 第四象限，评估要不要插进路线 |

**每次重排都要告诉他改了什么、为什么**——一句话就够（"你把压制烧结排除了，那条我只带一句，把时间挪到脱脂和烧结"）。他才有机会纠正你排错的地方。

⚠️ **不要因为"计划里写了"就把已经不相关的内容讲完。** 路线是为他服务的，不是清单打勾。

**难度贴着他当前的水平上沿走**：他刚好够得着、需要动点脑子的那一档。太浅浪费时间，太深会占满工作记忆、反而什么都留不下。判断依据是 glossary 里的「已掌握」条目和他最近几次回答的质量——**不要凭这个行业"应该多难"来定**。

⚠️ 反向也成立：**他跳过的不等于不需要。** 如果某一支是五类覆盖的必需项（尤其逐工序主干），即使他没兴趣也要带过，否则出师检验过不了——但可以压缩成一句话加一个"知道有这回事就行"。

### 路线写进 STATE.md，随时可改

```markdown
## 学习路线
| 状态 | 内容 | 备注 |
|---|---|---|
| ✅ 已讲 | 产品全景、MIM vs CNC/精铸的分界 | |
| ▶ 正在讲 | 喂料与脱脂 | |
| ⏳ 计划 | 烧结与变形控制 → 二次加工 → 关键参数 | |
| ⏸ 降级 | 压制烧结、金属 3D 打印 | 用户已排除，只带一句 |
```

这张表是他**直接改路线**的入口——比等你问对问题快。

### 拷问纪律

- 模糊答案继续追，不放过
- 他给的前提自相矛盾，当场指出
- 不替他做决定，但把每个选择的代价说清楚
- **不问"你想关注哪些维度"**——维度由落地九问定死，他不知道该关注什么，这正是他来找你的原因

## 四项必答

### 🔴 1. 能力边界（优先钉死）

- 他在产业链的哪个位置——自己做原料 / 买原料做零件 / 买零件 / 投资评估？
- 现有什么设备、人、场地、资质？
- **能控制什么，不能控制什么？**

**为什么排第一**：上一个项目前四轮 24 路全部在研究"怎么帮供应商把原料做好"，第五轮才确认委托方是成品厂不是原料厂——这一条改变了全部结论。产业链位置不是背景信息，**是筛选器**。

### 2. 目标产品 / 零件

要具体的，不要品类级的。

### 3. 目的

建厂 / 选技术路线 / 选供应商 / 判断值不值得进入。

### 4. 验收标准

**什么算"调研充分"？** 这一条要在开始前约定——多个权威框架独立要求"评估方与需求方必须在开始前就约定什么算充分证据"。

## 两份实时维护的文件

### unknowns.md · 四象限

**每轮对话之后更新**，不要攒到最后。

```markdown
# 认知地图 · 更新于 <日期>

## 已知的已知（known knowns）
| # | 内容 | 来源 | 状态 |

## 已知的未知（known unknowns）★ 这一栏直接生成任务书
| # | 问题 | 为什么重要 | 状态：未解决 / 第N轮已答 / 转实验 / 转询价 / 作废 |

## 未知的已知（unknown knowns）
用户有但没说出来的隐性知识——你从拷问里挖出来的
| # | 内容 | 怎么挖出来的 |

## 未知的未知（unknown unknowns）
盲区。学习阶段基本是空的，探索阶段每轮报告之后才会长出来
| # | 内容 | 哪一轮暴露的 |
```

📌 **第三、四象限是这个 skill 存在的理由。** 第一象限查文献就有，第二象限派队就能填，只有三、四必须反复回到用户这里。不写下来会蒸发。

### glossary.md · 术语状态

```markdown
| 术语 | 英文 | 一句话定义 | 状态 |
|---|---|---|---|
| 气雾化 | gas atomization | 用高压惰性气体把金属液流打碎成粉 | 已掌握 |
| 松装密度 | apparent density | 粉末自由填充时的堆积密度 | 已解释过 |
```

三档，晋级规则是机械的：

| 状态 | 含义 | 怎么晋级 |
|---|---|---|
| **未引入** | 还没在对话里出现 | — |
| **已解释过** | 你给过定义 | 首次解释后 |
| **已掌握** | **用户在回答里正确用过** | 观察到即晋级 |

不用打分，不用估等级。**可观测的机械判据 > 主观评分**，而且用户能看见这张表、能直接改。

它还是 `digest.html` 里 hover 定义的数据源，以及下一轮该往哪深挖的线索之一。

📌 **一个术语的定义一旦写进表里就是定版的。** 后面所有讲解、digest、最终报告都按这个说法用，不要中途换一套措辞——同一个东西两种叫法会让刚建立的认知散架。要改就改表，改完全局一致。

### resources.md · 这个行业的信息在哪

**验收标准是"能读行业周刊"，那就得告诉他有哪些周刊。** 边教边攒，收尾时成形。

```markdown
# <行业> 信息源

## 期刊与媒体
| 名称 | 语言 | 免费/付费 | 值得看什么 | URL |

## 行业协会与标准机构
| 机构 | 管什么 | 有没有公开资料库 | URL |

## 展会与会议
| 名称 | 频率 | 地点 | 议题偏向 | URL |

## 数据与检索入口
政府招投标 / 海关 HS / 专利库 / 环评公示 / 上市公司公告，各给具体入口

## 能问到人的地方
行业论坛、微信群/公众号、协会活动、本地产业集群
```

📌 **最后一节别省。** 有些判断只存在于从业者脑子里，文献和检索都拿不到——**知道去哪儿问，比多查一百次有用**。展会本身就是这个用途。

⚠️ 每条都要是**实际查证过、能给 URL 的**。这份表用户会照着去订阅、去报名，编造的条目代价直接落在他身上。

📌 这份表**三个阶段都用**：阶段一你照着找出师检验的真实文本，阶段二写任务书时它是信源清单，阶段三是报告的来源池。

### 覆盖面：五类都要有，主干是流程

**不看总条数，看类别覆盖。** 只堆孤立名词会造出"看得懂科普、看不懂行业话"的假象——这正是抢跑的典型症状。

| 类别 | 教什么 | 以口罩行业为例 |
|---|---|---|
| **产品全景** | 有哪些产品类型、按什么形态分、按什么等级分 | 平面 / 鸭嘴 / 杯型 / 折叠；按防护等级 N95、FFP2、医用外科 |
| **主要玩家** | 谁在做，各自占什么位置、强在哪一段 | 3M、Honeywell、国内头部各是什么角色 |
| **★ 全流程逐工序** | 从原料到成品**每一道工序，以及每道工序是干什么用的** | 树脂 → 熔喷 → 驻极 → 复合 → 成型 → 焊接 → 包装 → 灭菌，逐道讲作用 |
| **每道工序的工艺·材料·参数** | 这道工序有哪几种做法、用什么料、调哪些参数、常见问题是什么 | 驻极：电晕 / 水驻极 / 热驻极；助剂；电压、距离、时间 |
| **关键参数的定义** | 这个数**什么意思、怎么算、为什么重要、多少算好** | QF = −ln(1−η)/ΔP；MPPS；克重；压降 |

🔴 **第三、四类是主干，占教学时间的一半以上。** 按产线物理顺序走一遍，读者翻到哪一道就是哪一道——这和最终报告（`/tech-outlook`）的组织方式是同一根轴，学的时候按什么顺序，报告就按什么顺序读。

⚠️ **不教牌号和具体型号。** 认识 3M 是必要的，背 3M 9332+ 是浪费——那是查得到的东西，不是理解的门槛。同理不背标准编号的细则，只需知道**哪个标准管哪件事**。

## 眼熟 ≠ 记住

**看着眼熟制造虚假的掌握感。** 讲的时候全懂、讲完什么也说不出——这正是"和看短视频没区别"那种感觉的来源。

学习阶段的真正产出是**他在探索阶段能提出好问题**，那是"说得出"，不是"看得懂"。两者隔着一整层。

三个便宜的对治，穿插在教学里，不要单开一节：

- **回想** —— 讲完一道工序，**不看笔记**让他复述这道是干什么用的。答不出就是没进去，当场补
- **交错** —— 讲第 N 道工序时，问一个要回头连到第 N−2 道的问题（"脱脂没脱干净，会在烧结那步表现成什么？"）。孤立地讲每一道，讲完就散了
- **间隔** —— 隔几轮回头抽问前面的内容，不要讲完一段就永远不再提

⚠️ **知识和技能的难度处理相反**：讲概念时**难度是负担**，要尽量好懂；练"说得出"时**难度是工具**，费点劲回想才留得住。别把这两件事用同一种方式做。

## 出师检验（提议收尾之前必须做）

**别问"你觉得懂了吗"**——这问不出东西，而且把判断责任推给了还不知道自己缺什么的人。

**两半都要做：先测说得出，再测看得懂。** 只测后者会放过只有眼熟感的人。

### 上半场 · 说得出（不看任何材料）

请他**合上术语表和笔记**，做两件事：

1. **把全流程从头到尾说一遍**，每道工序一句话说它是干什么用的
2. **挑两三个关键参数**，说它衡量什么、大概什么量级算好

| 表现 | 判断 |
|---|---|
| 工序顺序和作用基本说得出，个别记混 | **过了** |
| 说得出名字，说不出作用 | 只有眼熟，**回去按"回想"重讲那几道** |
| 顺序都串不起来 | **远没到**，主干没建立 |

⚠️ 这是最容易暴露问题的一关，也是最容易被跳过的一关。**不要因为他刚才聊得很顺就免掉。**

### 下半场 · 看得懂（拿真实行业文本）

1. 找**一到两段真实的行业文本**——协会新闻稿、厂商技术公告、期刊摘要、展会议程。**原样给他，不要简化、不要挑简单的**
2. 请他**标出读不通的地方**（不是"不认识的词"，是"这句话在说什么我不确定"）
3. 看卡在哪：

| 卡点分布 | 判断 |
|---|---|
| 只卡在具体数值、型号、牌号 | **过了**——这些本来就不要求记 |
| 说不出讲的是哪道工序 | 补第三类，再测 |
| 知道是哪道工序，但不懂在调什么、出了什么问题 | 补第四类，再测 |
| 关键指标出现时不知道它衡量什么 | 补第五类，再测 |
| 整段抓不住主干 | **远没到**，回去继续教 |

4. 测完更新 `glossary.md`：他读通的术语晋级「已掌握」，卡住的补进表里

⚠️ 这是在测**材料**，不是在考他。措辞要落在文本上——"这段里哪几处你会想停下来查一下"，不是"你能不能看懂"。

## 收尾

**完成判据（四条全满足）**：

1. **出师检验上半场过** —— 不看材料能把全流程说下来，每道说得出作用
2. **出师检验下半场过** —— 读真实行业文本，卡点只落在具体数值、型号、牌号这一档
3. **glossary 五类全覆盖**
4. **四项必答全部有具体答案**，且用户说出"可以开始调研了"

⚠️ **前三条没到就提议收尾，是抢跑。** 只有第 4 条能被快速满足，正因为如此它最容易被当成全部——**实测已经发生过一次**。用户主动要走可以走，但要如实说明还差什么，并在 `STATE.md` 里记明"学习阶段提前收尾"。

收尾动作：

1. 把临时文件夹改名成研究主体（跟随用户已有的命名习惯，无日期后缀）
2. `unknowns.md` 出一版完整四象限
3. **出一份 `学习小结.html`**，见下
4. 写 `STATE.md`
5. **给出下面这段交接提示词**，让用户复制到新 session

### 学习小结（带得走的那张纸）

一份 HTML，**给的是压缩后的速查，不是重讲一遍**——设计成反复回看用的，不是初学用的。

- **全流程图** —— 每道工序一格，格子里一句话说作用
- **每道工序** —— 有哪几种做法 / 用什么料 / 调哪些参数 / 常见问题，四栏表
- **关键参数** —— 定义、怎么算、什么量级算好
- **术语表** —— 全量，带 hover 定义（写法见 [`digest.md`](digest.md)）
- **玩家与产品格局** —— 一张图能放下的程度
- **信息源** —— `resources.md` 的精简版：订哪几本、看哪几个协会、去哪几个展会

单文件、内联全部样式、主题自适应。写完用 `SendUserFile` 直接发给用户（`display: "render"`）。

📌 **这份的用途是他真去展会时打开的东西。** 按"站在展台前要查什么"来编排，不是按教学顺序。

不要在同一个 session 里继续进探索阶段——那样等于没拆。

### 交接提示词（原样输出给用户，路径替换成真实路径）

先用一句话说明要做什么，再给这个代码块：

````markdown
```
/tech-scout

继续 <绝对路径>/<主体>/ 的**探索阶段**。
先读 STATE.md 和 unknowns.md，然后按 references/explore.md 的八步走第 1 轮。
```
````

用 `SendUserFile` 把 `unknowns.md` 一并发给他看，让他在开新 session 之前有机会直接改地图。
